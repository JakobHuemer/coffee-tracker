# Issues 51 & 52 + ranking-badge overhaul

## Gotchas / non-obvious

- **Local `main` was ~25 merged PRs behind `origin/main`** (merge-base = local
  HEAD, so it was strictly behind, not diverged). Branched `feat/issues-51-52`
  off `origin/main`, not the stale local `main`. Watch for this next session.

- **Top Brewer was effectively unawardable.** `routes/rankings.js` already
  sorted by Elo and passed the Elo leader's id to `checkBadgeForRanking`, but
  that fn *re-computed* a separate winner by total caffeine and only awarded if
  `id === userId`. So `rank_1` only landed when the Elo #1 was also the caffeine
  #1. Now `checkBadgeForRanking()` takes no arg and is metric-driven: it reads
  each ranking badge's `requirement.metric` (`elo|caffeine|cups`) from
  `data/badges.js`, finds that board's leader, and awards. Adding a board =
  a badge entry + one SQL string in `RANKING_LEADER_SQL`.

- **Ranking badges are permanent** (never revoked when you lose the lead) and
  the award pass only fires on the `period=alltime` rankings fetch.

## Issue 51 (Stats teardown)

- Personal challenges removed **UI + backend**. Kept the `challenges` table and
  any existing personal rows (VALUES rule 2 — don't delete committed data);
  just dropped `POST /challenges` and stopped selecting/serving personal type.
  `checkAfterFirstChallenge` / `checkAfterChallengeWin` still fire for community.
- Community challenges moved to **Compete → Global → Challenges** section.
- Badges + Milestones are now standalone pages (`/badges`, `/milestones`)
  reached from Profile link-cards. Stats keeps only Goals/Rankings/Compare.
